# Klimr — Migrations Ledger (authoritative)

**This file is the single source of truth for what has been applied to the
production Supabase database.** It supersedes `GO_LIVE.md` (deleted Aug 2026 —
its migration instructions stopped at 0022 and were dangerously stale) and the
old `schema_combined_*.sql` snapshots (also deleted).

**How deployment works here (deliberate, recorded decision D5):** every
migration is pasted manually into the Supabase SQL editor by Gabriel, in
order, exactly as delivered in chat with its `-- 0NNN_name.sql —` header. The
Supabase CLI is intentionally **not** part of this workflow until the first
technical hire onboards. Migrations are proven in a scratch Postgres 16
cluster before delivery. Batches flagged **risky** (destructive DDL, data
rewrites, trigger/constraint changes on hot tables) require a proven recovery
path before they run.

**Recovery standard (Aug 2026).** The project has been on the Supabase **Pro**
plan since **Aug 5, 2026**, which runs **daily backups with 7 days of
retention**. Point-in-time recovery is a separate paid add-on and is *not*
included, so the granularity of recovery is "yesterday", not "five minutes ago".

- **Anything that writes, rewrites or drops data** — take a backup immediately
  before the paste (Supabase → Database → Backups), and note the timestamp in
  the row below. With 7-day retention and no PITR, a destructive migration whose
  damage is noticed on day 8 is not recoverable.
- **Grants / policies / views / functions only** — no row is touched, so a backup
  is not the recovery path. These ship with a *tested revert script* instead,
  e.g. `docs/ROLLBACK_0191_0192.sql`, which was applied to a replay of the full
  history and proven to restore the previous behaviour exactly.
- **Storage is not covered.** Supabase's daily backup is the Postgres database.
  Objects in `avatars`, `feed-media`, `credential-docs`, `tournament-payments`
  and the rest are not in it. A database restore would leave every media path in
  the database pointing at bytes that no longer exist. This is exactly the gap
  KCDX-053 names, and it is still open — Pro did not close it.

The app self-checks at boot: `lib/schema-check.ts` probes sentinel columns
and refuses to serve a production deploy against a database that is missing
migrations, pointing back to this ledger.
